# PLAN-BKG-001: Core booking rules

## Overview
Delivers the room catalog, reservation creation, the three validity rules and cancellation on an in-memory
repository, in the layered structure of ADR-BKG-001.

## References
- **Requirements**: RQ-BKG-001, RQ-BKG-002, RQ-BKG-003, RQ-BKG-004, RQ-BKG-005, RQ-BKG-006
- **ADRs**: ADR-BKG-001 (DEC-BKG-001, DEC-BKG-002), ADR-BKG-002 (DEC-BKG-003)

This plan implements the tasks in the format specified below.
---

## Tasks

### TASK-BKG-001: Implement booking domain model
- **Tier**: M
- **Status**: Done
- **Description**: Create the Python project (`service/pyproject.toml`), the domain objects (room,
  reservation, status), the domain errors and the room catalog.
- **Requirement refs**: RQ-BKG-001
- **ADR refs**: ADR-BKG-001 (DEC-BKG-001)
- **Acceptance Criteria** (Gherkin):
  - **Given** two rooms added to the catalog
  - **When** the catalog is listed
  - **Then** each room is returned with its identifier, name, capacity and open flag
- **Dependencies**: None
- **Assignee**: AI
- **Verification**: `python -m unittest tests.test_catalog tests.test_domain` (in `service/`): Ran 14 tests, OK.
- **Assumptions**: A room with a capacity below 1 is refused at creation (the requirement gives the minimum
  but not the reaction).

### TASK-BKG-002: Implement reservation creation
- **Tier**: M
- **Status**: Done
- **Description**: Define the repository port and the rule interface, implement the in-memory repository and
  the create-reservation use case that runs the rules it receives.
- **Requirement refs**: RQ-BKG-002
- **ADR refs**: ADR-BKG-001 (DEC-BKG-001, DEC-BKG-002), ADR-BKG-002 (DEC-BKG-003)
- **Acceptance Criteria** (Gherkin):
  - **Given** an open room with no reservation
  - **When** a valid reservation is requested
  - **Then** a Confirmed reservation is stored and its identifier is returned
- **Dependencies**: TASK-BKG-001
- **Assignee**: AI
- **Verification**: `python -m unittest tests.test_memory_repository tests.test_create_reservation` (in
  `service/`): Ran 12 tests, OK.
- **Assumptions**: Identifiers are generated by an injected factory, UUID strings by default.

### TASK-BKG-003: Implement overlap rule
- **Tier**: M
- **Status**: Done
- **Description**: Add the rule that rejects a request overlapping a Confirmed reservation of the same room.
- **Requirement refs**: RQ-BKG-003
- **ADR refs**: ADR-BKG-001 (DEC-BKG-002)
- **Acceptance Criteria** (Gherkin):
  - **Given** a Confirmed reservation from 10:00 to 11:00
  - **When** a reservation from 10:30 to 11:30 is requested for the same room
  - **Then** a conflict error naming the first reservation is raised
  - **And** a reservation from 11:00 to 12:00 is accepted
- **Dependencies**: TASK-BKG-002
- **Assignee**: AI
- **Verification**: `python -m unittest tests.test_overlap_rule` (in `service/`): Ran 5 tests, OK, including the
  back-to-back case.
- **Assumptions**: Cancelled reservations are ignored by the rule (a cancelled interval can be booked again).

### TASK-BKG-004: Implement room availability rules
- **Tier**: M
- **Status**: Not Started
- **Description**: Add the rule that rejects too many attendees and the rule that rejects a closed room.
- **Requirement refs**: RQ-BKG-004, RQ-BKG-006
- **ADR refs**: ADR-BKG-001 (DEC-BKG-002)
- **Acceptance Criteria** (Gherkin):
  - **Given** a room of capacity 6 and a room flagged closed
  - **When** 7 attendees are requested in the first, and any reservation in the second
  - **Then** a capacity error and a room-closed error are raised
  - **And** 6 attendees are accepted
- **Dependencies**: TASK-BKG-002
- **Assignee**: AI
- **Verification**: Pending.
- **Assumptions**: None

### TASK-BKG-005: Implement reservation cancellation
- **Tier**: M
- **Status**: Not Started
- **Description**: Add the use case that cancels a reservation that has not started and refuses one that
  has, using an injected clock.
- **Requirement refs**: RQ-BKG-005
- **ADR refs**: ADR-BKG-001 (DEC-BKG-001)
- **Acceptance Criteria** (Gherkin):
  - **Given** a Confirmed reservation that has not started
  - **When** it is cancelled
  - **Then** its status is Cancelled and the same interval can be booked again
  - **And** cancelling a reservation that has started raises an already-started error
- **Dependencies**: TASK-BKG-002
- **Assignee**: AI
- **Verification**: Pending.
- **Assumptions**: Cancelling an already Cancelled reservation does nothing and raises no error.
